# Capabilities V2

A capability states **what outcome must be possible**, not how it looks.

Example:

```text
booking → reserve an appointment or time slot
```

It does not imply a booking card, modal, floating button or calendar UI.

The standard registry includes contact, WhatsApp, booking, reservation, menu, catalog, gallery, location, map, reviews, lead capture, quote request, ecommerce, analytics, search, authentication, CRM integration, forms, media, video and social proof.

Each capability records:

- outcome
- primary actor
- journey roles (`discovery`, `trust`, `conversion`, `utility`, `proof`, `retention`)
- data needs
- dependencies / constraints when necessary
- criticality

The compiler places capabilities into Recipe stages by journey role. The final visual representation remains Experience-owned.
