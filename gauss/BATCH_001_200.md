# GAUSS batch 001–200 — controlled implementation milestone

This is a **batch delivery target**, not a claim that 200 scientific operators exist today. Only genuinely executable, registered, individually falsifiable operators are counted. Existing operators on `main` are retained; a draft branch is not an integrated or certified delivery.

## Definition of done for the 200-operator milestone

The milestone is NOT complete unless all of the following are true on one exact Git commit:

1. The executable registry has **exactly 200 unique operator IDs** across the eight GAUSS domains, with a real implementation for every ID and no aliases or arbitrary parameter presets counted as new algorithms.
2. The deterministic foundation fixture executes **every registered ID exactly once** and fails closed on any missing, duplicated, unsupported, or skipped operator.
3. Every newly added operator has documented mathematical semantics, numerical/size bounds, deterministic test inputs and output, an independent oracle or mathematical invariant, and invalid-input tests. An expensive exact solver must reject oversized instances rather than claim a partial answer is optimal.
4. All registered outputs pass GAUSS SHA-256 evidence checks and independent WALLE replay. Negative tests must forge outputs **and recompute all altered hashes**, then prove WALLE rejects them.
5. The existing Quantum participation policy remains enforced: no missing contributor bypass, no reused Ising receipt, and `hardwareExecution=false` for the internal simulator. No quantum advantage or 100% real-world effectiveness is inferred.
6. All applicable GitHub Actions workflows and deployment checks pass on the **same final SHA**; the published evidence artifact is downloaded and checked independently, the patch contains only declared GAUSS-related files, and `main` has not diverged unexpectedly.
7. No new external API, database, queue, service, secret, package dependency, customer mutation, or production activation is introduced by this milestone.

## Current draft work — 40/200, not merged

The mainline starts with 23 merged operators. The draft adds **17 actual implementations** to date: eight distinct bounded graph computations and nine bounded statistical operators. No absent operator, alias or input preset is counted. **40/200 = 20% of the first numerical milestone staged**, not delivered; **23/800 remains the integrated count** until an authorized, fully audited merge. The other 160 milestone operators have not been implemented and are not represented by placeholder entries.

The eight graph computations are nonnegative shortest path with witness, minimum spanning forest, integer max-flow/min-cut, strongly connected components, maximum-cardinality bipartite matching, DAG critical-path scheduling, bounded exact directed traveling-salesperson tour, and stationary PageRank. Independent oracles use Bellman–Ford, exhaustive spanning-forest/cut/matching/TSP searches, transitive closure, recursive critical-path calculation, and solved stationary linear systems.

The nine statistical computations are weighted linear regression, weighted isotonic PAV, Benjamini–Hochberg FDR adjustment, exact paired sign-flip enumeration, Fisher exact two-sided test using BigInt counts, Kaplan–Meier survival curve, Theil–Sen robust regression, split-conformal residual interval, and Bernoulli sequential likelihood ratio. Independent oracles use weighted normal equations, exhaustive monotone integer fits, BH suffix construction, recursive sign enumeration, integer hypergeometric enumeration, direct risk-set products, pairwise medians, explicit quantile ranks, and sequential prefix likelihoods. Inference from external populations requires matching assumptions, sampling, prospective validation and separately collected evidence; no fixture is a real customer claim.

Both modules have local bounded-case and malformed-input tests. Every new operator must also execute once in the GAUSS fixture, obtain SHA-bound output evidence, and fail a **rehashed forgery replay** in WALLE. Earlier SHA evidence never certifies later edits; rerun and independently inspect the final artifact before delivery.

**Progress accounting:** a draft registration is not a merge; the merge count is obtained only from the audited registry in `main`. The target 200 is not to be reported as achieved until its complete acceptance criteria are met. These algorithms solve supplied abstract inputs, not live customs routes, customer performance, or real-world delivery guarantees.
