# Motor 81: proveedor SQIsign nativo real (no certificado)

Este directorio contiene un transporte C para la API de firma **SQIsign p324_3**. A diferencia de las demostraciones de Vélu sobre campos pequeños, invoca las funciones criptográficas `crypto_sign_keypair`, `crypto_sign_signature` y `crypto_sign_verify` de una implementación completa. Un runner de GitHub obtiene la fuente desde `SQISign/the-sqisign` fijada al commit `7358e8786e2990fbf68ec2171606966d16872ddc` y compila el ejecutable con CMake. El binario y la clave secreta **no se guardan en Git**. Sin ejecutable y SHA-256 exigido por el llamador, GAUSS rechaza todas las operaciones de firma.

La dependencia es **código abierto de terceros, Apache-2.0** (con avisos de licencias adicionales en su `NOTICE`), descargado durante la compilación. No hay dependencia de un servicio remoto en tiempo de ejecución. No se debe presentar como implementación 100 % propia ni como seguridad de producción auditada. Un pin de commit limita la procedencia del código, pero no reemplaza revisión del código, reproducibilidad del binario, gestión de claves, pruebas de tiempo constante y evaluación criptográfica del esquema. La implementación upstream documenta límites de tiempo constante en módulos de enteros y cuaterniones: se prohíbe afirmar tiempo constante global.

Protocolos binarios: `--keygen` produce 83 bytes de clave pública + 270 privados; `--sign` recibe los 270 bytes secretos más un mensaje de hasta 65 536 bytes y produce 200 bytes de firma; `--verify` recibe 83 bytes de clave pública + 200 de firma + mensaje y responde un solo byte (0 o 1). El adaptador JS valida formato, longitudes, SHA-256 del ejecutable y ejecuta una copia privada para impedir sustituciones entre comprobación y ejecución. Nunca loguea material privado ni stdout/stderr de procesos fallidos.

La prueba positiva obligatoria en `.github/workflows/gauss-nemesis81-sqisign.yml` genera claves nuevas, firma, verifica, modifica mensaje/firma/clave y comprueba rechazo. Si falla la descarga, compilación, generación, firma o verificación, el job queda rojo; no hay fallback a Ed25519, a hashes o a las isogenias didácticas. Las pruebas negativas JS se ejecutan también en la suite general; **por sí solas no acreditan firmas reales**.
