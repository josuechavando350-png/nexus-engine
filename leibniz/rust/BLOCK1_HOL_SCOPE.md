# LEIBNIZ first-block formal higher-order proof kernel

## Exact semantics, not a universal decision procedure

The `hol` module checks finite proof certificates in classical extensional simple type theory (Church-style STT). Its types are an individual sort `ι`, truth values `o`, and function types `α → β` of arbitrary finite nesting. Universal and existential quantifiers range over arbitrary values at each constructed type, **including propositions, functions, predicates and predicates of predicates**. They are NOT enumerated over a finite symbol catalog. Constants are typed uninterpreted symbols, not observed facts. A closed theorem has no hypotheses; a theorem relative to hypotheses MUST disclose those premises. No arbitrary formula is declared proved because the verifier times out or cannot construct a proof.

Interpretation: every sort has a nonempty domain; `o` has Boolean values; functions have extensional interpretations, with function domains satisfying the lambda-definability closure of a general/Henkin model. Equality is identity at each type. `False`, implication and conjunction have classical truth conditions; quantifiers range over the domain assigned to their type. Lambda denotes a function; application evaluates that function. The independent code checks syntactic typing, capture-avoiding substitution, alpha equivalence and beta reduction; proof rules include introduction/elimination for implication, conjunction, universal and existential quantifiers; reflexive equality and substitution; proof-checked classical double-negation elimination; and extensionality for functions and propositions. Each accepted rule is sound under this interpretation, **subject to the implemented checks actually being correct**. The Rust test suite tests implementations; it is not a machine-checked metatheorem about its own soundness.

This is **not** general dependent type theory, full set-theoretic second-order semantics, proof search for arbitrary statements, the assertion that every true formula can be decided, an OWL-complete reasoner, a predictor, or a verification of external evidence. Higher-order validity under unrestricted standard/full semantics is not algorithmically decidable. The existing finite Horn engine is separate from the new HOL certificate checker; an external assertion must be explicitly supplied and authenticated by the consuming application before being used as a premise. The `hol` checker cannot infer that an arbitrary real-world source is true.

## First-block acceptance boundary

The existing 152 Rust test cases plus `tests/hol.rs` and `tests/block1_acceptance.rs` must all pass in a single commit with Rust formatting, strict Clippy, release build, and both real sample benchmarks. Failure in any command means no certification. Passing proves only the tested standalone core and the precise STT proof-verification surface described above; it does not certify every capability advertised for the universal product.
