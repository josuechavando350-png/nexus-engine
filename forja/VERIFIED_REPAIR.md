# FORJA: independent GAUSS regression verification (experimental)

Use `node forja/verified-repair.mjs --task=/absolute/path/to/task.json` to require **both** a genuinely failing targeted test and separately passing existing tests. No model is needed in native mode; see [NATIVE_REPAIR.md](NATIVE_REPAIR.md). The wrapper executes `verificationTests` first in a detached baseline worktree at the exact source SHA. It refuses to repair if any guard fails on the baseline. It then invokes the bounded repair agent in another detached worktree and reruns the unchanged guard tests against the candidate. Successful targeted tests **alone** never promote a candidate; guard failure produces `CANDIDATE_REJECTED_REGRESSION`. Guard test SHA-256 digests, executed assertion identities and the candidate diff hash are rechecked.

Add `"verificationTests": ["gauss/tests/an-existing-independent.test.mjs"]` to the native task. This pathname is illustrative; choose **existing, tracked** GAUSS tests that already pass. At most eight guard tests can be supplied; they must be distinct from the failing tests. The original source checkout must remain clean and at the same Git SHA, while proposals remain in detached worktrees for manual inspection. No test editing, GitHub writes, merges or deployments are authorized.

Automated tests exercise real failing/passing Node test executions using deterministic model-free arithmetic transformations as well as legacy fixture-model outputs. They demonstrate bounded acceptance and rejection, **not** broad mathematical correctness or the ability to program arbitrary operators. Even without a model, repository tests can run arbitrary host code: Git worktrees do not isolate processes, credentials, filesystems or networks. Run only on disposable unprivileged isolated Linux without production access or secrets. Full GAUSS/monorepo checks, independent mathematical oracles, resource isolation and human review are still required before a PR can be merged.
