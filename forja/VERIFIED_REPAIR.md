# FORJA: independent GAUSS regression verification (experimental)

Use `node forja/verified-repair.mjs --task=/absolute/path/to/task.json` to require **both** a genuinely failing targeted test and separately passing existing tests. The verified wrapper executes `verificationTests` first in a detached baseline worktree at the exact source SHA. It refuses to repair if any guard fails on the baseline. It then invokes the bounded repair agent in another detached worktree and reruns the unchanged guard tests against the candidate. Successful targeted tests **alone** never promote a candidate; guard failure produces `CANDIDATE_REJECTED_REGRESSION`. Guard test SHA-256 digests and the candidate diff hash are rechecked.

Add `"verificationTests": ["gauss/tests/an-existing-independent.test.mjs"]` to the repair task described in `forja/REPAIR_AGENT.md`. That pathname is illustrative; select **existing, tracked** GAUSS tests that already pass before executing. At most eight guard tests can be supplied; they must be distinct from the failing tests. The original source checkout must remain clean and at the same Git SHA, while proposals remain in detached worktrees for manual inspection. No test editing, GitHub writes, merges, or deployments are authorized.

The automated tests reproduce real failing/passing Node test executions with deterministic fixture-model outputs. They prove a narrow successful repair is accepted, an overbroad change that breaks existing behavior is rejected, and pre-existing guard failures cannot be misreported as new regressions. This is **not a real model evaluation** or comprehensive GAUSS verification. The model and tests can run arbitrary host code: Git worktrees do not isolate processes, credentials, filesystems, or networks. Run only on a disposable, unprivileged Linux environment without production access or secrets. Full GAUSS/monorepo checks, mathematical oracles, real-model benchmarks, resource isolation, and human review are still required before a PR can be considered for merging.
