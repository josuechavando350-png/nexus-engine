# One-time operator review redemption

`forja/approval-redemption.mjs` adds a **single-host, local** consumption step to the existing Ed25519 approval in `operator-approval.mjs`. It first re-verifies the trusted operator's signature, validity window, exact job, Git SHA, and current bytes of the successful four-stage job and its reports. Only then may it reserve a nonce. It never merges, deploys, signs on an operator's behalf, or grants production access.

Run `node forja/approval-redemption.mjs "$PWD" "$STATE_DIR" "$JOB_ID" /private/signed.json /private/trusted.json` after the documented challenge and offline human signing procedure in `OPERATOR_APPROVAL.md`. The private Ed25519 key stays **outside CI and the checkout**. The `STATE_DIR` must be an absolute, owned, non-symlink, private directory (0700 or stricter); `approval-redemptions/` is private and receipts are created mode 0600. Each UUID nonce is atomically reserved with `O_CREAT | O_EXCL | O_NOFOLLOW`, fsynced with its containing directory; a concurrent second process or later replay fails closed. The receipt includes the verified operator ID, source revision and evidence digest, but neither private key nor raw evidence.

A crash after reserving a filename is treated as a **consumed** nonce even if the receipt is partial. Never delete or recycle a nonce to work around a failure: request a fresh human challenge. Keep the state volume durable and backed up; removing/rolling back it removes replay protection. Multiple hosts need a shared transactional redemption store and independent trust anchoring before treating this as distributed protection. A privileged local attacker, rollback, directory replacement by an attacker with state-owner privileges, and remote disaster recovery are **not** solved by this module. Signing a manual review is **not** deployment authorization.

The dedicated CI executes a real four-stage SHA-bound job and verifies forged signatures are rejected, exactly one of two concurrent redeemers succeeds, later in-process and CLI replays fail, stored identity matches, private filesystem modes hold, and the source checkout remains pristine. CI uses only ephemeral fixture keys and does not provision a production signer or deploy.
