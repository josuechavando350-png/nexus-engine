# FORJA GitHub Actions state handoff (read-only CI profile)

`.github/workflows/forja-ci-state-handoff.yml` tests a real portable handoff without a purchased host, paid APIs, or user-supplied external credentials. It uses GitHub-hosted Ubuntu 24.04 runners, pinned GitHub Actions, Node 24, Git and the existing FORJA queue, snapshot and inspector implementations. GitHub's automatic checkout token is read-only. The workflow never opens PRs, deploys, executes arbitrary user jobs, accesses production systems, or creates operator keys.

The producer checks out the exact triggering SHA with a pristine worktree, runs a real four-stage evidence job, inspects its five registered source-byte proofs, creates a bounded offline snapshot of private state and verifies its manifest. It packages **only the snapshot directory** in a tar artifact. The snapshot ID, manifest SHA-256, job ID and tar SHA-256 are independently passed through GitHub job outputs. The consumer is a distinct, fresh Ubuntu runner: it independently checks out the same SHA, verifies the tar digest against the previous job's output, extracts into a new private backup root, verifies the manifest digest, restores into an absent private state root, recomputes the old job's four reports and source bytes, and completes and verifies a **new** job without replaying the old job. A failed check fails the workflow.

**The artifact is not encrypted or independently signed.** It contains only Git-tracked source-derived evidence generated for CI, not client data, private keys, production approvals or real secrets. Do not reuse this workflow to export private data. The digest in a job output detects transfer damage or artifact tampering relative to the producer, but a compromised producer or GitHub account can alter both the artifact and its reported digest. This does not attest to GitHub as an independent trust authority.

A fresh runner and tar artifact are **not** a physical host reboot, continuous 24/7 service, proof of durable storage beyond artifact retention, crash-consistent live backup or independently authorized production restore. GitHub Actions artifacts expire according to their retention settings; no free-cost guarantee is made for account usage. FORJA's optional persistent `systemd --user` deployment remains a separately unverified operational profile. The broader FORJA v1 certification remains open in issue #435, and unregistered Nexus sources remain `NOT_AUDITED`.
